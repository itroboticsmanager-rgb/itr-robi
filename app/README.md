# Device app

Застосунок пристрою: обличчя, режими, координація сенсорів, детекція
обличчя, локальний стан та CRM-клієнт. Виконавчих механізмів немає —
у v1 пристрій не має рухомих частин (`D-019`).

## Стек

Python 3.11+ і pygame-ce (SDL2). Вибір `provisional`: рішення `D-015` ще
відкрите і закривається бенчмарком, а не вподобанням. Тому рендерер
тримається за інтерфейсом — якщо вимірювання на цільовій платформі
покаже, що його не вистачає, замінюється **він**, а не застосунок.

Залежності свідомо мінімальні: `pygame-ce`, `segno`, `websockets`,
`psutil`. Усе інше — стандартна бібліотека.

## Запуск

```bash
python -m venv .venv
.venv/Scripts/pip install -e ./app          # Linux/macOS: .venv/bin/pip
.venv/Scripts/pip install pytest
```

```bash
robi -c app/config/device.example.toml
```

Корисні прапорці:

| Прапорець | Навіщо |
|---|---|
| `--offline` | не підключатися до CRM |
| `--headless` | без вікна, SDL dummy — для CI та вимірювань |
| `--seconds N` | зупинитися через N секунд і надрукувати метрики |

Клавіші у вікні: `F1` — сховати HUD, `N` — імітувати дотик телефона до
NFC-мітки, `Esc`/`Q` — вихід. Клік мишею рахується як дотик до екрана.

## Fake CRM

Реальної CRM ще немає, тож розробка ведеться проти локального сервера
(`D-023`). Він уміє те, що на справжньому backend відтворити важко:

```bash
python app/tools/fake_crm.py                        # звичайний цикл
python app/tools/fake_crm.py --scenario duplicate   # той самий command_id двічі
python app/tools/fake_crm.py --scenario expired     # прострочена команда
python app/tools/fake_crm.py --scenario phishing    # чужі домени в QR
```

Сценарій `phishing` — головна перевірка `D-038`. Очікуваний результат:

```text
[fake-crm] 3a8d5000b81c: rejected (domain_not_allowed)
[fake-crm] 4a7f81a953e6: rejected (scheme_not_allowed)
[fake-crm] 4f66f3a2dae5: rejected (credentials_in_url)
[fake-crm] a9b9c3a60ee2: rejected (domain_not_allowed)
```

Якщо хоч одне посилання дійшло до екрана — зламано межу, заради якої
allowlist узагалі існує.

## Бенчмарк

Інструмент, яким закриваються `D-015`, `D-021` і `D-022`:

```bash
python app/tools/benchmark.py --resolutions 800x480 1280x720 --seconds 10
```

Запускати на робочому ПК як базу й на кандидатах платформи як порівняння.
Цільовий дисплей для цього **не потрібен** — підійде будь-який наявний
монітор.

Дивитися треба на `median` і `p95`, а не на середній FPS: обличчя з
регулярними провалами виглядає гірше за стабільно повільніше.

> **Застереження.** У headless-режимі SDL не виводить кадр на екран, тож
> вимірюється вартість рендеру на CPU без презентації й vsync. Саме це й
> потрібно для порівняння платформ, але абсолютні числа не є FPS, який
> побачить людина.

## Тести

```bash
.venv/Scripts/python -m pytest tests -q
```

`tests/unit/` — логіка без заліза й без графіки. `tests/integration/` —
справжній `App` у headless-режимі.

Два набори варті окремої уваги, бо вони охороняють рішення, а не код:

- `test_policy.py` — allowlist доменів (`D-038`);
- `test_vision_boundary.py` — межа `D-027`: перевіряє, що подія від
  vision не має полів під кадр чи ідентифікацію, тож заборона не може
  зникнути непомітно при рефакторингу.

## Структура

```text
app/src/robi/
├── bootstrap.py     # складання застосунку й головний цикл
├── config.py        # завантаження й валідація конфігурації
├── events.py        # спільний словник подій і намірів
├── state/           # системні стани й координатор режимів
├── modes/           # mascot, qr
├── ui/              # обличчя, QR-екран, HUD
├── vision/          # детекція обличчя; віддає події, не кадри
├── hardware/        # адаптери ToF, NFC, виходів
├── integration/     # CRM-клієнт і allowlist посилань
└── health/          # метрики кадру й ресурсів
```

Реальних адаптерів поки немає: усе працює на fake-реалізаціях, і це
навмисно. Хвиля 0 у `docs/roadmap.md` не потребує жодної закупівлі.

## Що ще не зроблено

- режими `info`, `nfc`, `voice` — координатор чесно відхиляє команди на них;
- реальні адаптери периферії замість fake;
- provisioning, watchdog, оновлення й rollback;
- `payment.confirmed` і повний lifecycle платіжного посилання (`D-035`).
